# `lib/`-moduulit — täysi referenssi

Tämä on paketin **täysi** `lib/`-moduuliluettelo, yksi rivi per moduuli. Se irrotettiin
`CLAUDE.md`:stä, koska se on hakuteos eikä joka session kontekstia: taulukkoa luetaan
tiedostonimellä silloin kun sellainen vastaan tulee, ei alusta loppuun.

**Lähde on koodi, tämä on peilaus.** Jos tarvitset funktiotason yksityiskohtia, lue itse
tiedosto. `CLAUDE.md` §7 pitää sen osan, joka ei ole hakuteosta: **jaetut primitiivit, joita
ei saa monistaa**. Alla olevat `§`-viittaukset osoittavat [`CLAUDE.md`](../CLAUDE.md):n
lukuihin.

| Tiedosto | Vastuu |
|---|---|
| `action-service.py` | **Ainoa Python-tiedosto.** Ohjaamon HTTP + auth -ydin: fail-closed `tailscale whois`, kolmikerroksinen CSRF, audit-loki, `execve` dispatcheriin — ei koskaan koske gh:hun itse |
| `action-token.sh` | Ohjaamon jaettu CSRF-token. Bearer-salaisuus: ei koskaan `status.json`iin, lokiin eikä kommenttiin |
| `archive.sh` | Terminaalitilaisten run-dirien siirto `run-issues-archive/`iin. PR-suoja on paikallinen, ei gh-kutsu |
| `ab-arm.sh` | A/B-kokeen haara (#308): onko koe määritelty (`RUN_ISSUES_AB_CLAUDE_*`), haaran arvonta, kirjaus `run.json`:iin kerran per ajo (`ab_arm_assign`) ja luku sieltä (`ab_arm_of`). Ei tunne malleja eikä efforteja — `claude-call.sh` valitsee haaran B arvot |
| `claude-call.sh` | Yksittäisen orkestroidun askeleen claude-CLI-kutsu (timeout, lokitus, finalisointi, käyttörajan tekstipohjainen tunnistus ja oma paluukoodi) ja aina päällä olevan järjestelmäkehotteen toimitus: toimintasopimus + koodausstandardi yhdistettynä — myös PR-vahti kutsuu tästä `load_repo_principles_file`ia |
| `claude-profiles.sh` | Claude-tilausprofiilien järjestetty lista (#295): jäsennys, tunnistetiedoston tarkistus, profiilikohtainen täysi-tila `deadline-file.sh`:n päällä, ensimmäisen vapaan valinta ja aikaisin nollautuminen. Vaihtosilmukka asuu `claude-call.sh`:n `call_claude`ssa |
| `deadline-file.sh` | Koneen laajuisten perääntymisporttien yhteinen yksirivinen `<deadline> <tag>`-tilatiedosto: fail-soft luku, atominen kirjoitus. Jaettu `rate-limit.sh`:n ja `usage-limit.sh`:n kesken |
| `env-bootstrap.sh` | Pakettimanagerin ja kohderepon `.nvmrc`-Node-version tunnistus S7b:n fail-fast-asennusporttiin |
| `epic.sh` | Epic-tason automaatio: ajolabelien propagointi, `needs-human`-eskalaatio, valmiuskommentti. `_epic_post_attention` on epicille kirjaamisen jaettu primitiivi (label ennen markerillista kommenttia), jota myös `epic-review.sh` käyttää. Best-effort (aina rc 0); `_epic_child_pr_refs` erottaa lukuvirheen (rc 1) "ei PR:iä" -tuloksesta, ja kutsuja päättää sietääkö sen |
| `epic-review.sh` | Epicin valmistumiskatselmus. `epic_review_collect` kokoaa aineiston (kriteerit, lapsijoukko, PR-viitteet ja yhdistetty muutospinta `lib/pr-surface.sh`:n kautta) yhtenä markdown-lohkona, **fail-closed**: mikä tahansa lukuvirhe ⇒ rc 1 ja tyhjä tuloste. `epic_review_run` ajaa promptin `09-epic-review` `call_claude`n kautta ja `epic_review_parse` jäsentää verdictin kolmeen lopputulokseen (`criteria_met`, `findings`, `launch_failed`); `epic_review_findings` antaa löydökset muodossa `kriteeri\|kuvaus`. Ei GitHub-kirjoituksia — kirjauksen tekee juuren `epic-review.sh` |
| `git-remote.sh` | Multi-remote-apurit: yksi klooni voi pollata useaa GitHub-orgia. Myös jaettu aikarajallisen `git fetch`in primitiivi (`runner_git_fetch_bounded`), jota `worktree.sh:refresh_origin` ja `version.sh:runner_fetch_throttled` käyttävät |
| `github-app-auth.sh` | Opt-in GitHub App -identiteetti. Kattaa kirjoitukset **ja** raskaimmat luvut |
| `fix-rate.sh` | Koosteen jälkikorjausmittari (#314): watchlist-repojen jaksolla yhdistetyt `auto-run/`-PR:t sekä niistä peruutetut ja jälkikorjatut. Kolme REST-listausta per repo, sivutus vain jakson verran (§5.4); luokittelu on puhdas jq-funktio (`fix_rate_classify`). Fail-soft |
| `escape-trace.sh` | `escape-trace.sh`-jäljityksen puhtaat jäsentimet ja luokkapäätös: `tiedosto:rivi`-viittaukset rungosta (`escape_trace_refs`), auditoitu SHA (`escape_trace_audited_sha`), commit-viestin `Auto:`/`(#N)`-tulkinta (`escape_trace_msg_link`), runner-haaran issue (`escape_trace_issue_from_branch`) ja `escape_trace_classify` (runner / peritty / tuntematon + ratkaisutapa). Runner-haaran tunnistus kulkee `runner-pr.sh`:n `RUNNER_BRANCH_PREFIX`in kautta |
| `evolution-findings.sh` | Evolution-vaiheen tuloksen (`EVOLUTION_RESULT`, `EVOLUTION_DELTA_PSI`) **ainoa** jäsennin. Orkestraattori (PR-kuvaus) ja `evolution-digest.sh` (kooste) lukevat saman funktion kautta, jotta kooste ei voi lakata näkemästä sitä, minkä PR näyttää |
| `gitignore.sh` | Pitää **kohderepon** `.gitignore`n ignoroimassa ajoaikaiset artefaktit |
| `host.sh` | `runner_host`: koneen lyhyt konenimi yhdestä paikasta, nelivaiheisella varapolulla (`hostname -s` → `hostname` ensimmäiseen pisteeseen → `$COMPUTERNAME` → `unknown`). **Ei koskaan palauta tyhjää** — §5.6:n fail-closed-portit lukisivat tyhjän hostin vieraaksi koneeksi |
| `host-gate-notice.sh` | Host-portin "muuttuja puuttuu" -rivin toimitus: stderr **ja** skriptin oma loki, kerran. Erillään `poller-config.sh`:sta, jotta sen puhtausväite säilyy — tämä kirjoittaa levylle |
| `hook-runner.sh` | Synkroninen commit, joka ajaa post-commit-hookit loppuun ennen paluuta |
| `issue-images.sh` | Issuen kuvien poiminta ja lataus, jotta agentit näkevät ne |
| `issue.sh` | GitHub-issue-operaatiot. Sisältää paketin **ainoan** poimintakyselyn (`pick_oldest_candidate`), lapsijoukon **ainoan** resolvoinnin (`list_epic_children`) ja ajopolkulabelien **ainoan** lukijan (`issue_run_path`) sekä `assignees`-syntaksin **ainoan** ALLOW/DENY-jaon (`_pick_assignee_sets_jq`), jota myös runnerin kirjoittaman issuen reititys `pick_assignee_route` käyttää sekä kommenttien luottamussuodatuksen (`issue_trusted_json`) ja kehotteen kommenttiosion **ainoan** muotoilijan (`issue_comments_block`). Varauksen purun sääntö on `unclaim_keeps_assignee`: ennen claimia ollut `@me`-assignee (`run.json`:n `self_preassigned`) säilyy, ja `cleanup-run.sh` lukee saman säännön |
| `jq-binary.sh` | `jq --binary` Windowsissa (§5.8). Paketin ainoa exportattava funktio; entry pointit sourcettavat sen |
| `labels.sh` | Label-hallinta REST-API:n kautta (ei `gh issue edit --add-label`) |
| `locking.sh` | Issue-kohtainen lukkohakemisto, atominen `mkdir(2)`:lla |
| `log-rotate.sh` | Kokoon perustuva lokirotaatio. Erillään `poller-config.sh`:sta, jotta sen puhtausväite säilyy — tämä kirjoittaa levylle |
| `machine-env.sh` | Koneen env-tiedoston sourceaus **kutsujan etuoikeudella** (§5.5). Jaettu `orchestrate.sh`:n ja `pr-watch.sh`:n kesken, jotta sääntö on yhdessä paikassa |
| `paths.sh` | Lukkojuuren ja lokihakemiston **alustakohtaiset oletukset** (`uname -s`: Darwin ⇒ macOS-polut, kaikki muu ⇒ XDG state). Haara on tarkoituksella ei-valkolista, jotta `MINGW64_NT-*` osuu XDG-haaraan |
| `poller-config.sh` | Host-portti, watchlistin resolvointi ja repon poimintaehdot (labelit, valinnainen `assignees`) sekä repomerkinnän skalaariavaimet (`poller_watchlist_repo_value`, #373) samalla polkuvertailulla. Erillinen, koska poller itse exittaa source-hetkellä vieraalla koneella eikä olisi testattavissa. Kirjoittaa levylle ei koskaan; ainoa ulkoinen komento on watchlistin `jq`-luku |
| `security-scan.sh` | Valinnaiset deterministiset skannerit (#336): gitleaks ja osv-scanner diff-tilassa (`base..HEAD`, skannerien konfiguraatio merge-basesta) tai auditointitilassa (koko repo). Tulos merge-portin `sev\|conf\|loc\|desc`-muodossa; puuttuva skanneri on kirjattu no-op, epäonnistunut ei ole koskaan puhdas; ajettujen määrä `security_scan_ran_count` (#382). Kuluttajat: merge-portti (`pr-watch.sh`) ja koko repon auditointi (`security-audit.sh`) |
| `finding-issues.sh` | Auditointilöydös → issue (#339), auditoinnista riippumaton: sormenjälki (lähde, tiedosto ilman riviä, luokka-avain), piilomarkeri, indeksi **yhdellä** REST-labelilistauksella (`state=all`, §5.2/§5.4) ja päätös `create`/`exists`/`reopen`/`dismissed`, valinnainen assignee (createssa samassa kutsussa, reopenissa vain assignoimattomalle) sekä auto-run-raja (repo voittaa koneen, epäselvä ⇒ `none`). Kuluttajat: `security-audit.sh` ja `coherence-audit.sh` (label `coherence`, ei koskaan poimintalabeleita) |
| `audit-schedule.sh` | Koko repon auditoinnin ajastus pollerista (#340): laji → skripti -taulukko (`audit_kind_script`, ainoa laajennuskohta; lajit `security`, `coherence` ja `dependency-scan`), väli (repo `.<laji>.audit_interval_days` > watchlistin `<laji>_audit_interval_days` (#373, `audit_machine_interval`) > koneen `RUN_ISSUES_<LAJI>_AUDIT_INTERVAL_DAYS`, epäselvä ⇒ ei ajastusta) ja käynnistyshetken yksirivinen tilatiedosto (`lib/deadline-file.sh`), O(1) per repo × remote. Lisäksi (#360) skriptien velvoittava kutsumuoto, kelvottoman välin diagnoosi (`audit_interval_problem`), kerran-kirjaus (`audit_notice`) ja istuntonimi (`audit_session_name`/`_parse`, jota myös `status.sh` käyttää). Viimeisimmän tuloksen luenta (`audit_last_outcome`, #373) jakaa exit-koodin tulkinnan uusintapäätöksen kanssa (`audit_rc_outcome`). Viimeksi onnistuneesti auditoitu commit (`audit_sha_file`, #382) siirtyy skriptin pending-tiedostosta vain onnistuneella täydellä ajolla, joten muuttumaton koodi ohittaa agenttikierroksen. Spawn on pollerin `_dispatch_audit_pass` |
| `repo-audit.sh` | Koko repon auditointien yhteinen runko (#342): remoten ja oletushaaran resoluutio, irrotettu väliaikainen worktree ja sen siivous, käynnistystarkistus, löydösindeksi, agenttikutsu **vain luku -portteineen** (siirtynyt HEAD tai likainen puu ⇒ exit 3) ja löydössilmukka, jolle auditointi antaa avain-, label-, otsikko- ja runkofunktionsa. Kuluttajat: `security-audit.sh` ja `coherence-audit.sh` |
| `pr-surface.sh` | PR-joukon yhdistetty muutospinta (`review_pr_surface`): tiedosto per rivi ja viitteet, jotka koskivat siihen. Kutsuja valitsee viitteen (epic-katselmus: lapsi-issue, koherenssiauditointi: PR). **Fail-closed** — yksikin lukukelvoton PR ⇒ rc 1 ja tyhjä tuloste |
| `merge-gate.sh` | Yleisen merge-portin puhtaat osat (#334): tulosmuodon jäsennys (käynnistysvirhe ei ole koskaan puhdas), vakavuusraja (repo voittaa koneen) sekä headin aiempi tulos ja yritysmäärä `state.jsonl`in hännästä. Silmukka ja pidätys ovat `pr-watch.sh`:n `pr_run_merge_gate`ssa |
| `pr-watch-lib.sh` | PR:n luokittelu ja merge-päätös irrotettuna testattavaksi |
| `deps.sh` + `deps.tsv` | Paketin ainoa koneluettava riippuvuusluettelo (#376): taso, laajuus, Homebrew- ja apt-asennus, lisenssi, käyttötarkoitus. Puhdas bash-lukija; S0-portti, asentajan raportti ja `docs/dependencies.md`:n taulukko johdetaan siitä |
| `preflight.sh` | Jaettu riippuvuustarkistus. Korjauskomennot yhdestä lähteestä (`preflight_install_hint`, pakettien vihjeet `deps.sh`:sta). `preflight_claude_cmd_unusable` on PR-vahdin agenttien ja `security-audit.sh`:n yhteinen käynnistystarkistus |
| `rate-limit.sh` | Rate-limitin **tekstuaalinen** tunnistus ja jaettu perääntyminen (§5.1) |
| `run-terminate.sh` | Elävän ajon turvallinen lopetus **kutsuttavana funktiona**. Irrotettu pollerista, joka `exit 0`si source-hetkellä; `stop-run.sh` ja `run-epic.sh --stop` käyttävät samaa polkua monistamatta turvalogiikkaa |
| `runner-pr.sh` | Runnerin omien haarojen ja PR:ien tunniste (#375): `RUNNER_BRANCH_PREFIX` on etuliitteen ainoa määrittely (haaranimen muodostus, portit, purku ja auditoinnit lukevat sen), ja `runner_merged_prs` on mergettyjen runner-PR:ien ainoa listaus (semanttinen portti ja koherenssiauditointi). Sivutus fail-closed: täysi sivuraja, joka yhä ulottuu ikkunaan, ei ole valmis vastaus |
| `semantic-gate.sh` | Semanttisen merge-portin laukaisimen puhtaat osat (#341): hakemistojoukot ja niiden leikkaus, mergettyjen `auto-run/`-sisarten suodatus REST-listauksesta (ei-taulukko on virhe, ei "ei sisaria") ja basen first-parent-committien jako sisarille. Git- ja gh-kutsut ovat `pr-watch.sh`:n `_pr_semantic_trigger`issa |
| `sibling-runs.sh` | Saman repon sisarajot cycle reviewlle (#337): avoimet runnerin PR:t **yhdellä** REST-listauksella per repo ja tämän koneen elävät run-dirit, muuttuneet tiedostot paikallisista refeistä. Neuvoa-antava: lukuvirhe renderöityy promptiin virheenä, ei tyhjänä listana eikä estä ajoa. `list_sibling_runs` on irrotettu S6:sta sarjoitusta varten |
| `state.sh` | Ajon durable-tila `<run-dir>`-hakemistossa |
| `status-github.sh` | `status.sh --github`-rikastus. Ei omaa CI-rollupia eikä merge-päätöstä — kutsuu `pr-watch-lib.sh`:n omia |
| `status-read.sh` | `status.sh`:n puhtaat luku- ja luokittelufunktiot. `_iso_to_epoch` asuu täällä, jotta poller ja näkymä laskevat iän identtisesti |
| `teardown.sh` | Label-vetoisen purun turvaportit **kutsuttavana funktiona**: lukko, run-dir-inventaario, `completed`-ajon PR-portti, haaran PR-portti ja remote-haaran poisto (opt-in, `auto-reset`), `cleanup-run.sh`-delegaatti. `auto-clean.sh` ja `auto-reset.sh` ovat sen ohuita lopputuloskerroksia |
| `usage-limit.sh` | Clauden käyttörajan koneen laajuinen portti (#294): takarajan tallennus (myöhempi voittaa), voimassaolo ja `status.sh`:n kentät. Tunnistus asuu `claude-call.sh`:ssa kutsun vieressä |
| `version.sh` | Ajossa olevan version ja submodule-pinnin näkyväksi teko. Fail-soft: puuttuva `.git` ⇒ `?` |
| `worktree.sh` | Ajokohtaiset git-worktreet kohderepossa |
| `issue.test.sh`, `render-prompt.test.sh` | Yksikkötestit (`verify_claim`, `render_prompt`) |
